03 / Streaming & tool calls

Set stream: true for SSE. Text tool calls support tools, tool_choice and valid tool messages. Your client is responsible for executing tools.

HTTP 200 or the first chunk does not prove successful settlement. Wait for a complete [DONE], then inspect task status. Missing usage, a broken stream or a deadline retains the hold for reconciliation, without automatic supplier failover.

The initial implementation allows at most 3 channel attempts. Async upstream calls and stream reads share a 90-second window. Actual ingress limits can be stricter.

05 / Idempotency is not response replay

The same Idempotency-Key returns 409 and an original task reference, without calling the model again. We do not store prompts or answers, so we cannot replay an answer. Before regenerating content, check the original state and understand that a new task may incur another charge.

reserved means a hold exists; settled means accounting is complete; pending_reconciliation means the result or cost needs review. failed or reconciled_released means the call was not settled and the hold was released. Use the actual task response as the source of truth.

06 / Handle errors, not blind retries

HTTPWhat to do
401 / 403Check the gateway key, email verification and account access. Do not automatically switch suppliers.
402Insufficient credit or customer budget. Resolve it before submitting a new task.
409Inspect the original task reference. An idempotency conflict does not mean nothing executed.
428Missing Idempotency-Key. Supply a stable task ID.
429Rate limited. Respect Retry-After and retain the task ID; check whether it was already accepted.
502 / 503 / 504May indicate platform budget, unavailable supply or reconciliation. Inspect the error type and original state; never assume no charge.

08 / Key permissions and lifetime caps

When creating a key in the console, optionally set allowed_models, max_output_tokens and spend_limit_microusd. Spending uses integer microUSD (1 USD = 1000000). Leaving fields empty inherits account and platform limits, not unlimited credit.

The lifetime cap does not reset. Settled customer charges and pending reservations both consume it; reconciliation holds do not expire automatically. BYOK uses customer provider spend. Limits are immutable: revoke and create a new key to change them. A new key does not increase account credit or budgets.

GET /v1/models is filtered by key scope. A disallowed model returns 403, excessive output returns 422, and insufficient key capacity returns 402. If output length is omitted, the platform default must also fit the key limit. Input safety rejection releases the reservation and returns a task ID; duplicate idempotency keys do not execute again.
