# Key 权限与累计消费上限验收

范围：商业中转 PRD P0-02/P0-07 的 Key 独立控制。不是缩回 BYOK，也不是整站商用上线声明。

## 已实现契约

`POST /v1/keys` 仍需客户网页登录态，只显示一次本站 Key。新增以下可选字段：

| 字段 | 规则 |
|---|---|
| `allowed_models` | null/省略表示账户可用模型；否则为 1–100 个当前上架模型 ID，不可重复。不授予平台本来不允许的模型权限 |
| `max_output_tokens` | null/省略沿用平台限制；否则为 1–1000000 的严格整数。实际限制是 Key、模型和平台上限的交集 |
| `spend_limit_microusd` | null/省略表示不设额外 Key 上限；否则为 1–10000000000 的严格整数 microUSD |

消费上限是 **Key 生命周期累计上限**，不是月预算，不自动重置。限制创建后不可修改；改限制需吊销并新建 Key。新建 Key 不能增加钱包余额或绕过客户预算/站点成本熔断。首发不引入自定义 Key 速率档位，仍沿用既有服务端限流。

`GET /v1/keys` 仅返回自己的 Key 元数据与三个策略字段，并返回 `spent_microusd`、`reserved_microusd`、`available_microusd`。没有 Key 上限时 available 为 null，不表示钱包或平台无限量。BYOK 支出是客户供应商费用；商业模式支出是本站实际客户扣费，不是平台上游成本。

`GET /v1/models` 按当前 Key 模型范围过滤。调用不允许的模型返回 403 `key_policy_rejected`，输出超限返回 422，Key 消费不足返回 402 `billing_rejected`。未传输出长度时，平台默认长度也必须满足 Key 上限，不静默截短。

## 账本与并发不变量

- 每次 admission 在 User → ApiKey 行锁内复核权限与额度；预授权插入逻辑任务后一起提交。
- Key 支出直接从逻辑任务汇总，不从 attempt 重复累加，也不另建易失配计数器。
- `settled/under_reserved` 计实际客户扣费（BYOK 计核验后供应商成本）；`released` 不占用；其他状态保守保留全额预授权。
- 结算/释放/待对账状态转换统一先锁 User，避免与新请求竞争产生虚假可用额度。
- 人工确认的 BYOK 历史实际成本可能超过预授权或 Key 上限；必须如实保留成本，剩余额度显示 0，新请求阻断，不伪装未发生费用。
- 所有预算预授权现在在内容审核外呼之前完成。审核拒绝/明确不可用会记录审核元数据并释放预留，不调用模型、不收模型费用。相同幂等键再次提交查询原任务，不重跑审核。进程异常留下的占用仍需现有对账流程处理。
- 本站支出控制不等于供应商绝对不多收费；上游异常收费依旧需要待对账处理。

## 验证证据

本地最新结果：412 项 Python 测试通过，分支覆盖率 82%；45 项前端测试和 TypeScript 类型检查通过。一项既有 Starlette/httpx 弃用警告。GitHub CI 需以对应提交的实际运行结果为准。

- Python 回归覆盖非法策略、模型/输出拦截、预算不足时审核和模型均不外呼、精确额度边界、已结算扣费继续占用累计上限、未知成本持有、释放恢复、独立 Key、跨客户隔离、BYOK 历史核验超额阻断。
- SQLite 迁移真实执行至 `0015_key_policy`，历史 Key 的新增字段全为 null，ORM/schema 对齐；存在受限 Key 时降级拒绝，防止丢失权限边界。
- 本地可丢弃 PostgreSQL 16 执行完整 CI 角色/ACL/假 Vault 门禁：三个客户共享站点限额、16 次相同幂等请求只产生一份预留；16 个不同请求并发争用一个受限 Key 只允许一个，释放后额度恢复。假 Vault 不证明真实 Supabase 加密或商户/供应商接通。
- 浏览器使用 loopback 隔离夹具，真实走本地 Key 创建接口，确认策略字段落库、双语切换不重建 Key/不丢设置、移动端不溢出；既有支付恢复/身份流程仍为模拟验收。
- 界面沿用现有控制台排版，仅增加可展开策略区和账目摘要。截图：忽略目录 `release-artifacts/key-policy-en-mobile.png`，已目视检查，无真实密钥截图。

重复执行：`coverage run --branch -m pytest -q`、`coverage report --fail-under=80`、`npm run check`；隔离数据库运行 `scripts/ci_postgres_gate.sh`；loopback 夹具依次运行 `tests-browser/checkout.cjs` 和 `tests-browser/console-locale.cjs`。

## 发布、回滚与剩余边界

新 schema head：`0015_key_policy`。本轮只迁移可丢弃测试数据库，没有生产迁移、真实收费或上线。生产必须先明确对象与批准，备份后迁移。精确 schema 版本检查仍保留；不能直接把旧镜像指向新数据库。

受限 Key 存在时禁止 schema 降级（即使只吊销也不自动删历史策略）。发生问题优先关闭新调用、保持账本与策略，前向修复；需要旧版本时须在隔离恢复环境验证兼容迁移方案，不能靠删除账目/限制回滚。

累计聚合复用请求索引，成本随历史任务量增长；真实规模压测仍待完成。不得在未迁移权威累计基线前清理或归档逻辑任务，否则会重置累计额度。没有宣称并发数/SLA或生产容量。

仍待完整商业目标：运营后台完整人机流程、正式支付 SDK/商户和供应商核验、正式服务政策、受保护预发布、真实小额支付/调用/退款、部署恢复与容量验收。该功能包通过不等于整站已可收款上线。
