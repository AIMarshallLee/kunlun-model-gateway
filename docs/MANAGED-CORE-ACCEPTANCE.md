# 商业中转内核：实现与验收边界

本次交付是 `managed_gateway` 商业内核开发候选，不是整站完成、不是真实收款或公网运营。当前主产品目标以 [商业 PRD](PRD-overseas-commercial-api-gateway.md) 为准；原 BYOK 手册不代表新的产品范围。

## 已实现并有本地证据

- 平台模式：客户注册并验证邮箱，创建本站 API Key；不要求客户提交上游 Key，且禁止访问客户 BYOK 凭据写入接口。
- 复用支付订单、余额、追加型双式账本；模拟结账确认、10 次相同支付事件单次入账、全额退款已纳入新模式回归。模拟协议适配器不等于正式支付 SDK。
- 客户余额与平台上游成本分别预授权，费用均用整数 microUSD；补充大整数计价舍入回归，消除浮点误差。
- `platform_daily_budgets` 持久化 UTC 日成本占用和已结算成本。余额、客户预算或平台成本不足时停止新外呼，相关预授权事务整体回滚。
- PostgreSQL 平台专用 Vault 凭据域，不复用客户身份；操作需短期、分权限的运维令牌。密钥可轮换、吊销；operation ID 防止重复执行，原操作元数据可查询。
- 平台凭据函数限定 executor、固定 SECURITY DEFINER owner/search_path；runtime、Supabase anon/authenticated 和 executor 均无平台私有表直接访问权限。审计表禁止更新、删除、截断。
- 平台模式必须带 `Idempotency-Key`。同键返回原任务状态，不能再次外呼；不保存正文，因此不能重放原回答。
- 每次 attempt 记录渠道、凭据版本、上游价格和费用；客户只按逻辑任务结算一次。仅明确未处理的连接失败或 429 可切换。通用 5xx、认证错误、不确定超时、已开始流式响应不自动重试。
- 首发配置最多 3 个固定官方渠道，不能内联密钥或任意 URL。异步上游调用及流式读取共用 90 秒绝对时间窗口；过期不自动续开任务。数据库、入口平台本身的超时另需预发布验收。
- 缺失用量、成本超过预授权、超时和断流保留客户及平台占用，进入人工对账。人工确认真实成本可记录超支，不修改历史上限；超出当日平台上限后继续拒绝新请求。
- 原 BYOK、旧测试模式兼容门禁保留；生产不允许使用测试适配器或测试支付开关。

## 新增接口

| 接口 | 运维权限 | 行为 |
|---|---|---|
| `GET /ops/channels` | `channels:read` | 当前渠道元数据；不返回 Key |
| `PUT /ops/channels/{provider}` | `channels:write` | `secret`、`operation_id`、`reason`；配置/轮换平台 Key |
| `POST /ops/channels/{provider}/revoke` | `channels:write` | `operation_id`、`reason`；停止后续解析；Vault 清理失败时保持禁用并标记待清理 |
| `GET /ops/channel-operations/{operation_id}` | `channels:read` | 查询原提交记录，不返回正文或 Key；404 不代表仍在途的操作绝对未执行 |
| `GET /ops/platform-budget` | `metrics:read` | UTC 日上限、占用、已结算成本、剩余额度及待对账请求数 |

以上接口仍必须位于受保护运维入口后。现有账户冻结、支付退款和人工对账 API 继续使用各自权限。本次没有完成完整可视化运营后台，不能用这些接口冒充管理员产品体验已验收。

## 预算与账务规则

1. 受理顺序：验证身份/Key → 冻结零售价格 → 客户余额与预算占用 → 平台成本占用 → 事务提交 → 外呼。
2. 同一客户的受理/结算/释放遵守一致锁顺序；外呼不持有数据库事务。
3. 每日首次成功受理冻结当日数据库上限；提高进程配置不能提高当天已冻结上限。单个实例使用更低配置时仅该实例更严格；全站降额需后续受审计的控制面，不可直接手改数据库。
4. 平台成本占用按所有候选渠道中较高的输入/输出价格和保守 Token 上界计算。它不是实际费用；最终费用来自有效 usage 和冻结价表，真实供应商账单仍要核对。
5. 跨日结算或人工对账回写请求原来的 UTC 日，不挪到新一天，也不自动释放前一天的未知费用。
6. 在途已经读取的旧 Key 无法通过吊销撤回；吊销阻止之后的密钥解析。密钥事件结果不确定时先查原 operation ID，再由运维处理，不自动轮换重试。
7. 同一模型名的模拟跨渠道测试不证明真实供应商提供等价模型。模型映射、缓存/思考 Token 等实际计价维度未验证前，不加入正式售卖目录。

## 验证入口和证据等级

本轮本地结果：386 项 Python 测试通过（其中商业模式专项 26 项），分支覆盖率 82%；TypeScript 类型检查及 37 项既有测试通过；PostgreSQL 16 独立夹具的迁移、权限负例和跨客户并发门禁通过。存在一项既有 Starlette/httpx 弃用警告。云端 CI、容器完整构建和实网状态必须另看对应执行结果，不能由这些本地结果推断。

```bash

.venv/bin/coverage run -m pytest -q
.venv/bin/coverage report --fail-under=80
npm run check
```

- 新模式专项：注册/验证/入账/调用、未知成本占用、全局限额回滚、SSE、429 切换、5xx/401 不切换、人工对账、原操作查询、无效目录拒绝、模拟结账与全额退款。
- 全量 Python 和既有 37 项 TypeScript/OpenCode 插件测试属于本地回归；不替代云端 CI 或实网验收。
- `scripts/ci_postgres_gate.sh` 使用明确确认的可丢弃本地 `kunlun_ci` 数据库。执行迁移 0014、角色/函数/表/列权限、审计防修改和故意破坏 ACL/触发器后的拒绝验证。假 Vault 明文夹具仅用于权限和事务证明，不证明 Supabase 实际加密。
- `scripts/verify_managed_postgres.py` 已加入该 CI 门禁：3 客户、16 次重复逻辑任务仅 1 个占用；24 个竞争请求只放行预算能覆盖的 2 个；交错受理/释放无余额透支，逐笔账本平衡。

## 尚未完成，不得跳过

2. 正式支持/条款内容、完整可视化运营后台与完整客户路径验收。英文首页/中文切换、当前售价目录与公开接入说明见 [公共站点验收](PUBLIC-SITE-ACCEPTANCE.md)；现有控制台模块已有 [英文/中文本地验收](CONSOLE-LOCALE-ACCEPTANCE.md)，不代表所有商业功能或运营后台完成。
3. 正式模型渠道与商业用途依据、实际模型/售卖价表/额外收费维度、真实跨供应商切换。配置确认布尔值不是法律或供应商授权证明。
4. 商业模式专用 Vercel/Compose 环境模板和受保护预发布：当前旧生产模板按 BYOK 配置，不能靠改一个开关直接收费上线。
5. 独立安全复核、真实 Supabase Vault、真实小额购买/调用/退款、日志隐私检查、入口限制、备份恢复、负载和重部署/回滚演练。
6. 本次代码未执行真实账号变更、生产迁移、真实付款、生产部署；客户数量、收入、毛利、获客和复购均未验证。

## 升级与回滚

新 schema head 为 `0014_managed_gateway`。不要在生产直接执行本地测试命令；迁移前需确认精确生产对象、备份和批准。新迁移是追加式的，但有运行时精确版本检查，不能把旧镜像直接指向新 schema。

紧急停止新调用时，先在入口阻断新流量/关闭相应渠道，保留在途请求与占用；不能删预算、支付或审计表当作回滚。迁移 downgrade 主动拒绝，需另行制定保留账本和凭据的批准方案。本次没有迁移任何生产数据库。
