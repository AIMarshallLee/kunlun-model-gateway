# 模型售价版本与上下架：本地验收

范围是商业网关 PRD P0-10 的模型目录运营能力。这里的模型、订单、上游和支付均为隔离测试数据，不是实际营业、供应商报价或毛利证据。

## 已实现的合同

| 权限 | 接口 | 合同 |
|---|---|---|
| `models:read` | `GET /ops/models?limit=20&offset=0` | 分页模型目录；`id` 是该模型最早价格行的稳定 ID；`price_id` 是当前版本 ID |
| `models:read` | `GET /ops/models/{id}` | 当前版本和最近 100 个价格版本；更多时 `history_truncated=true` |
| `models:write` | `POST /ops/models/{id}/price` | 新建价格/上下架版本，并在同事务写入审计；不修改既有版本的价格数值 |

以上端点仅供 `managed_gateway` 使用；客户令牌不被接受。网页另需 `console:read`。生产入口保护、可信运维签发和强身份验证仍须按运维手册独立验收。

发布请求示例（金额为整数 microUSD，百万 microUSD 等于 1 美元；示例不是商业报价）：

```json
{
  "action": "publish",
  "expected_version": 1,
  "operation_id": "operator-price-reference-001",
  "reason": "Synthetic price-version acceptance only",
  "input_microusd_per_million": 2000000,
  "output_microusd_per_million": 3000000,
  "max_output_tokens": 1024
}
```

- `publish` 创建下一版本并上架，必须提供两个正整数售价及输出上限。只允许当前配置支持、且有供应商适配目录的模型；售价不得低于任一已配置供应商单价；输出上限不得超过平台上限。无免费促销/亏损定价豁免，也不在该接口新增任意模型或供应商。
- `unpublish` 创建下一版本并下架，不接受价格字段。重复下架、过期 `expected_version`、重复 `operation_id` 返回 409；客户端刷新对象与审计后再决策，不能自动换操作 ID 重发。
- 价格历史 ID 不能替代稳定目录 ID；不存在或不是最早版本的 ID 返回 404，避免为同一模型产生多个锁入口。
- 审计含操作主体、scope、对象、原因、操作 ID、前后版本/上下架状态。报价数值可通过对应历史版本追踪；没有客户正文、回答或供应商密钥。
- 公共价格页和 `/v1/models` 读取当前已上架目录。下架后新调用在模型外呼前拒绝；已经获得预授权的请求可继续完成。

## 并发、重启与历史账目

最早价格行是稳定锁入口。PostgreSQL 中请求预授权先取共享行锁，调价/上下架取排他行锁；预授权提交后释放锁，不在上游网络请求期间持锁。版本和审计一起提交，数据库既有 `(model, version)` 与 `operation_id` 唯一约束作为额外防线。

每笔 `ModelRequest` 已冻结当时的版本及输入/输出单价；结算不读取最新售价。价格修改和下架不重算历史收费，不取消旧占用，也不把不确定上游成本清零。

商业模式启动时，环境价格只初始化数据库中不存在的模型。已有模型的数据库版本优先，重启不重新上架或恢复旧配置价格。调整供应商成本配置后，运营必须重新核对当前数据库售价；发布时的价格下限校验不证明未来成本、手续费、重试、退款或支持费用已覆盖，不保证利润。供应商适配配置存在也不证明正式供应资格或实时可用。

本批未新增数据库价格不可变触发器；“不改历史价”是本接口合同及测试结果，不是拥有直接数据库写权限的人也无法改价。应用不能混用商业模式与旧 BYOK/legacy 启动进程访问同一业务库；旧模式仍有不同的配置播种语义。

## 界面与验收

沿用独立运营台的“核查 → 准备命令 → 确认一次”流程，英文默认、中文可切换。当前版本、上下架状态、两种售价单位及输出上限可直接查看，历史在技术元数据展开区。语言切换不丢价格输入、不替换已确认的操作 ID、不执行写请求。隐藏的价格输入不参与下架命令校验。

本地复现：

```bash
.venv/bin/python -m pytest tests/test_ops_prices.py -q
.venv/bin/python -m coverage run --branch -m pytest -q
.venv/bin/python -m coverage report --fail-under=80
npm run check
# 另开终端，启动可丢弃 loopback 夹具，再用现有 Playwright 运行
.venv/bin/python tests-browser/ops_fixture.py
node tests-browser/ops.cjs
# 仅明确标记为 kunlun-ci-disposable 的本机隔离数据库
bash scripts/ci_postgres_gate.sh
```

本地结果：18 项价格专项测试、440 项 Python 全量测试通过，分支覆盖率 83%；48 项 TypeScript 测试及类型检查通过。证据覆盖独立读写权限、严格输入/原因校验、历史版本不能作为锁 ID、无配置供应商拒绝发布、过期版本/重复动作拒绝、旧价结算、下架无外呼、重启不覆盖、重新上架。隔离 PostgreSQL 16 实际 handler 并发验证两次 v1 改价只产生一次成功/一条审计，下架与预授权竞争后新受理被拒绝，历史结算仍使用 v1。

浏览器模拟验收覆盖只读不显示操作、确认前零写、双语命令不变、调价成功后丢响应不重发且保留原操作 ID、价格 v1→v2→下架 v3→上架 v4、原价未改、下架公共目录为空，并保留既有冻结、对账、模拟退款丢响应和移动端回归。截图在忽略目录 `release-artifacts/ops-price-desktop.png`，不是生产页面证据。

## 未完成与回滚

本批没有新增 schema 迁移，仍为 `0015_key_policy`。回滚前停止新的价格动作；优先前向修复或保留本批商业播种和模型锁改动。直接退回旧应用可能在启动时覆盖价格/重新上架，不能作为安全回滚。价格业务回退应发布一个数值取自旧价的**新版本**，不删除新旧记录、不改历史账本。

尚待完整商业目标：告警聚合及通知、渠道轮换操作体验、真实管理员身份与入口、正式支付 SDK/商户与供应商资格、政策、受保护预发布、生产容量/恢复验收及真实小额支付—调用—退款闭环。没有因这批通过而标记整站“只补账号即可营业”。
