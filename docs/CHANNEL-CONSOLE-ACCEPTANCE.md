# 平台渠道运营台：配置、轮换与禁用

范围：商业 PRD 的 P0-06 / P0-10，接入既有平台专用 Vault 管理接口。不是 BYOK 业务替代，不是正式供应商授权、健康探测或生产部署声明。

## 页面与接口

`/ops/console` 的 `Supply status / 渠道状态` 现在支持渠道详情、配置／轮换、禁用，以及按原 operation ID 查询操作记录。

- `GET /ops/channels` 保留原 `channels` 元数据数组，新增 `catalog`：只列服务端允许目录中的渠道，包括尚未保存凭据的渠道。字段包含 provider、渠道 ID、凭据版本、状态、pending_cleanup、配置优先级、配置模型和允许主机；不包含 Key、Vault secret 引用或成本推断。
- `GET /ops/channels/{provider}` 返回同一 `catalog` 行的 `{channel: ...}` 详情。需要 `channels:read`；未知渠道 404，Vault 不可用 503，不把读取失败显示成正常。
- `PUT /ops/channels/{provider}` 和 `POST /ops/channels/{provider}/revoke` 沿用原有 `channels:write`、operation_id 和原因要求。PUT 配置新密钥并启用渠道；revoke 停止后续平台凭据解析，不代表在供应商处吊销 API Key，也不能撤回已取得密钥的在途模型调用。
- `GET /ops/channel-operations/{operation_id}` 沿用 `channels:read`，只查已提交的操作元数据。找到记录不证明当前凭据版本或当前健康；404 也不证明在途变更未执行。

页面要求短时运维 token，同时拥有 `console:read` 才能进入工作台。只读角色没有凭据变更动作。只有 `channels:write`、没有 `channels:read`，不能通过界面浏览渠道。生产仍须受保护入口、真实强认证和明确变更授权。

## 状态和动作

| 状态 | 界面解释 | 可见写动作（需写权限） |
|---|---|---|
| unconfigured | 允许目录中存在，尚未保存凭据 | 配置已批准的平台 Key |
| enabled | 凭据已启用；不是健康或供应商资格已验证 | 轮换或禁用 |
| disabled | 平台不再解析该凭据 | 配置新 Key 并启用 |
| pending_cleanup | 已停止使用，但 Vault 清理未完成 | 核查原操作后，另行批准的清理重试；不显示新 Key 输入 |

模型和优先级来自服务端配置，不能通过此页面增加任意转发 URL 或不明供应商。变更后的详情读取会同步更新相应列表项；列表和详情仍是读取时快照，不是实时监控。

## 密钥和确认边界

1. 只在密码输入框输入已获明确授权的平台 Key；不是客户本站 Key，不是账号订阅 Cookie。原因字段不能包含密钥或其他秘密。
2. 点击“核对操作”后清空输入框；密钥只由页面闭包暂持，不进入确认 JSON、操作结果、URL、localStorage 或 sessionStorage。确认预览包含固定渠道、method、operation_id、原因、观察到的版本及“密钥单独提供”说明。
3. 切换语言不更换已经准备好的命令。取消、改变动作、改变原因、切换对象／模块、锁定或离页会废弃暂存密钥；需要重新输入才能准备轮换。真正发送时将密钥单独加入 PUT 正文，不把它加入供展示的命令对象。
4. 请求结束后清除处理函数持有的密钥引用；JavaScript 字符串／浏览器网络内存不能被应用保证立即擦除，不宣称密码学意义的内存清零。需使用受控运营终端；浏览器开发者工具、扩展及供应商自身保留策略不在页面保密保证内。
5. 配置／轮换 PUT 现在与 POST 一样受客户端单次写入保护。断线或超时显示结果未知，不自动再次发送。页面保留已提交的非秘密 operation ID，供只读查询；锁定会清除页面记录，因此离开前应把必要的非秘密操作号保存到获批准的运维记录。
6. 原服务使用数据库串行写入，不提供 `expected_version` 条件更新。确认中的版本是观察值，不是版本锁；并行操作员必须协调，变更后必须核对当前渠道。界面没有把这项限制伪装成乐观并发保护。

正式环境实际轮换、禁用或清理真实 Key 仍需明确对象和批准；本批只在 loopback 隔离夹具使用无法调用供应商的合成字符串。

- `tests-browser/ops-channels.cjs`：只读与写权限、配置／轮换／禁用、取消和锁定清理、预览不含 Key、中英文固定命令、丢失 PUT 响应后只查询原操作、清理待处理分支、列表同步、手机布局；操作前后模拟模型调用数不增加。
- 启动 `.venv/bin/python tests-browser/ops_fixture.py --channels`，再使用现有 Playwright 环境运行 `node tests-browser/ops-channels.cjs`。此夹具中的 backup 只是固定允许目录的合成条目，不证明真实第二家供应商或跨渠道容灾。
- 原运营台、拒付、返还浏览器回归分别使用无参数、`--chargebacks`、`--returns` 的新 fixture；不要混用已被测试修改的临时数据。

本批本地结果：509 项 Python 测试通过，分支覆盖率 84%；49 项 TypeScript 测试及类型检查通过。渠道管理、原运营台、拒付、资金返还四套浏览器流程均通过；桌面与 390px 中文手机截图已目视检查，未发现横向溢出或密钥展示。以上使用合成凭据与临时数据，不是实际供应商、真实收款或生产环境验收。

无 schema 迁移，head 保持 `0017_chargeback_returns`。回退 UI 提交不等于回退已执行的凭据变更；不要恢复旧 Key、删除审计或降级财务表来回滚页面。发生不确定结果时，先核查原操作与当前渠道，按批准的运维流程处理。

剩余商用要求：正式供应商及模型计费核验、真实 IdP/MFA 与入口、正式支付 SDK、受保护预发布、真实小额支付／调用／退款、恢复和容量验收。此界面不解除这些门槛。
