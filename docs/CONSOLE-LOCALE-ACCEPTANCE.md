# 英文客户控制台与中文切换：本地验收

本次范围是商业 PRD 的现有客户控制台英文体验，不是整个商业 PRD 完成。正式支付 SDK、完整运营后台、供应商计费验证和生产验收仍待完成。

## 实现

- 控制台、邮箱验证与密码重置页面默认英文，`?lang=zh` 选择中文；导航延续语言，页面内切换无需重新登录。
- 账户、Key、预算、订单恢复、模型测试、用量、余额流水、提示和操作确认均有英文文案。数字和日期使用所选语言的格式；机器状态码、模型 ID 和账本标识保留原值。
- 翻译仅处理已知界面文字；变量一次性插入，不当作 HTML，不递归替换。客户名称、输入、一次性 Key 与模型回答保持原样。
- 切换只重绘和读取本客户状态，不重发注册、购买、Key、预算或模型调用；不重建 CAPTCHA，不修改表单输入和模型/套餐选择。已隐藏的 Key 不重新显示。
- 模型测试显示结果仅暂存当前页面以重绘，退出清空；服务端仍不保留正文。订单查询失败会清掉旧快照，切换语言不能复活旧付款链接。
- 英文界面对未收录的中文服务端错误提供带 HTTP 状态的保守英文指引，不推测细节、不声称请求未执行；中文界面保留原服务端错误。
- 新增同源 `console-locale.js`，不引入翻译服务、外部字体或浏览器持久化。
- 增加无 JavaScript 提示，并将 CSP 的 `form-action` 改为 `none`：表单操作只走现有 fetch API，避免脚本未加载时原生 GET 把密码写进 URL。托管支付仍以合法 HTTPS 链接进入，不依赖本页原生表单提交。

## 验证与证据等级

本地：395 项 Python 测试通过，分支覆盖率 82%；TypeScript 类型检查与 45 项测试通过。一项既有 Starlette/httpx 弃用警告。

新增 4 项语言测试覆盖所有现有静态 HTML 标签/属性、中文 JavaScript 消息、英文插值完整性、语言切换、客户变量不被递归替换以及保守错误提示。原有凭据闭包、CSP、身份片段清理门禁保留并补充原生表单禁用断言。

浏览器验收在 loopback 可丢弃 `managed_gateway` 夹具进行，使用隔离 Chromium、内存邮件与假支付适配器：

1. 英文初始界面无遗漏中文（语言按钮除外），桌面与 390×844 移动端已检查。
2. 新模拟用户注册、邮箱验证、错误密码英文提示、登录、创建 Key、设置预算、购买订单显示和恢复正常。
3. 反复切换英文/中文，没有新增任何写请求；注册/重置输入、Key 名称和一次性 Key 不变，关闭 Key 后不会再次显示。
4. 模型回答展示使用浏览器拦截的合成中文/HTML 样式文本，证明原样展示、无 HTML 注入、切换不重发调用；此项不证明真实上游调用或计费。
5. 模拟订单查询 503 后切换语言，旧付款链接保持隐藏。
6. 忘记密码、邮件恢复片段、重置密码成功；旧 API Key 实际返回 401。邮件链接通过本地内存测试信箱获取，未验证真实邮件投递。
7. 关闭 JavaScript 后点击登录，捕获 CSP 表单阻断；没有发送凭据请求，URL 没有凭据查询参数。
8. 既有中文购买恢复浏览器回归通过。

## 重复执行

```bash
# 终端一，固定 loopback，禁止部署这个夹具
.venv/bin/python tests-browser/checkout_fixture.py

# 终端二，需要现成的 Playwright 和 Chromium
# 先执行购买回归，再执行语言验收
node tests-browser/checkout.cjs
node tests-browser/console-locale.cjs

npm run check
.venv/bin/coverage run -m pytest -q
.venv/bin/coverage report --fail-under=80
```

测试信箱路由只存在于 `tests-browser/checkout_fixture.py`，不在应用包或生产镜像中。浏览器将配置的 HTTPS 示例域名请求转给本地夹具，不访问真实支付或模型网站。浏览器脚本为本地验收，未加入云端 CI。

## 发布边界与回滚

未执行账号变更、生产迁移、真实交易或生产部署。无数据库 schema 变化；预发布回归可恢复上一应用版本，但不应撤销已添加的原生表单保护，也不能删订单或账本来回滚。

这次完成的是“现有客户模块可用英文操作”，不是凭空补齐尚不存在的商业模块。完整运营后台、细粒度 Key 权限/限额验收、正式支付、正式服务政策、商业部署和真实小额闭环须继续逐项完成。
