# 海外商业大模型 API 中转站 PRD

状态：开发目标基线；供应商、商户、价格和目标生产资源仍待具体确认。本文根据用户最新要求修正产品范围，不表示已获得生产部署、付款、账号变更或数据库迁移批准。

## 1. 概要

建设面向海外开发者、小团队和昆仑自有工具的商业模型 API 聚合站。客户在本站注册、购买调用额度、创建本站 Key，通过统一 API 调用允许销售的模型服务；本站完成接入、客户计费、供应商成本核算和运营支持。

主产品不要求客户自带模型 Key。BYOK 可作为独立可选模式保留，不再替代商业中转目标；公众号内容准备助手属于消费本网关的独立业务应用，不混入首发范围。

## 2. 负责人和决策边界

| 角色 | 责任 |

| Codex / 开发执行 | 代码差距审计、架构与接口、前后台实现、迁移与测试、交付文档、受控部署和验收准备；如实报告阻塞 |
| 首批测试用户 | 使用自己的测试账户完成注册、充值、调用和账单确认；目前未确认任何真实客户 |

本地开发、模拟测试和部署准备可以继续；采购、充值、真实收费、修改凭据、生产数据库迁移和生产发布必须有明确对象与批准。不要求用户通过聊天发送密钥。

## 4. 目标与完成标准

一句话：让客户用一个账户、一份调用额度和一个 Key 使用多个已接入模型，并清楚看到每次扣费。

首发验收目标（目标，不是已达成数据）：

1. 一名新用户无开发者代操作完成注册、邮箱验证、购买额度、取 Key、模型调用及用量查询。
2. 相同支付事件重放 10 次只入账一次；相同调用幂等键并发重试只产生一个逻辑任务。
3. 两个独立租户对 Key、余额、订单、任务和日志的跨租户访问全部拒绝；管理员操作可追踪。
4. 并发预授权不能使可用余额为负；余额不足、客户预算不足或站点成本熔断时拒绝新请求，拒绝项不得外呼。
5. 入账、预留、结算、释放、退款/冲正的每一步能核对；成本不确定项保留占用并进入人工对账，不按超时自动当作免费。
6. 非流式、SSE 流式、工具调用、OpenCode 配置与一个自有工具接入样例通过验收；自有工具的真实项目另行指定，不能拿样例冒充客户集成。
7. 新模式全量测试、CI、干净镜像构建、受保护预发布验收、真实小额支付/调用/退款及重部署/恢复演练全部通过，才标记可商业上线。

## 5. 首发客户与价值

服务需要统一 API、统一账单和成本限制的独立开发者、小型团队，以及昆仑现有套壳工具。模型可选范围、单次输出上限、并发、速率和支持时间明确展示。

价值假设是减少多供应商接入和账单管理工作，而不是保证全网最低价、永不封号、永不断线或必然赚钱。客户付费意愿和渠道获客能力必须另行验证。

## 6. 产品与商业规则

- 客户购买本站服务调用额度；客户 Key 只访问本站，平台上游凭据不得交给客户。
- 首发采用预付调用额度、按明确展示的模型用量计费；只接一个正式支付渠道，使用支付方托管收银台，不自存卡号/CVV。
- 售价和上游成本分开。金额使用整数 microUSD；1 USD = 1,000,000 microUSD；展示可换算成美元，内部不使用浮点余额。
- 首发只支持已实现且可核对的计费维度。若模型有缓存、思考 Token、工具附加收费或长上下文阶梯价，必须支持并验证相应计价，否则不加入售卖目录。
- 供应商成本记录每一次 attempt；客户按冻结的售卖规则结算一次逻辑任务，不因平台内部重试重复扣费。对于可能已发生但无法确定的上游费用，暂停自动处理并对账。
- 每个请求冻结模型售价、上游计价、版本和预授权规则；调价不改历史订单与已受理任务。模型和供应商名称映射明确，不静默换成低质量模型。
- 模型价格、套餐金额、是否有购买额度有效期、部分退款规则、税费/支付手续费处理，发布前在配置和客户条款中确定，不用未经核验的假价格收款。首发不做自动到期清零、不做提现或余额转账。
- 退款和拒付依据支付方确认的状态执行账本冲正；不足抵扣时进入冻结/追踪流程，不删除历史、不自动向客户追加扣款。具体售后条款需由运营方确认。
- 托管供应商渠道必须具有支持本站具体商业用途的依据。没有完成核验的渠道保持禁用，不得用订阅共享账号、Cookie、逆向接口或不明低价 Key 代替。

## 7. 解决方案

### 7.1 客户路径与必备页面

首页/价格 → 注册 → 邮箱验证 → 购买额度 → 支付确认入账 → 创建本站 Key → 复制接入配置 → 调用 → 查看扣费和状态 → 续充或联系支持。

首发客户页面：英文首页（中文切换）、模型与实时生效价格、注册/验证/登录/找回密码、控制台总览、购买额度/订单、Key 管理、用量与账单导出、简单调用测试、公开 API 文档、服务条款/隐私/退款说明、异常状态与支持入口。不做完整聊天产品、内容历史或复杂社区。

### 7.2 功能模块与验收

| ID | 首发功能 | 必须验收 |
|---|---|---|
| P0-01 | 注册、登录、邮箱验证、恢复密码、退出与滥用限流 | 未验证账户不能购买/调用；验证码和恢复链接一次性且过期；错误不泄露账户存在性 |
| P0-02 | Key 创建、仅显示一次、吊销、可选模型范围和限额 | 仅存摘要；越权或吊销后拒绝；不显示上游 Key；恢复密码后的凭证处理有明确提示 |
| P0-03 | 购买额度订单、托管支付、签名回调 | 金额/币种/商户/订单核验；支付页面跳回不能触发入账；重复/乱序通知正确处理 |
| P0-04 | 钱包及追加型账本 | 购买、赠送测试额度、预留、扣费、释放和退款分开；管理员调整必须原因、审计和冲正，不可直接编辑余额 |
| P0-05 | 统一模型 API | `/v1/models` 和 `/v1/chat/completions`；非流式、SSE、工具调用；模型/输出/正文大小校验；错误兼容且脱敏 |
| P0-06 | 平台供应商渠道 | 平台专用 Vault 域、密钥轮换/禁用、模型映射、优先级和健康状态；不得复用客户身份伪装平台凭据 |
| P0-07 | 预算、限流与成本熔断 | 用户余额、用户/Key 预算、站点日成本上限分别生效；并发不能绕过；阈值阻断不能只发告警 |
| P0-08 | 路由、故障切换与幂等 | 仅允许安全、明确未处理的失败切换；不对通用 5xx、认证/参数错误、不确定超时或已出流重复外呼；有独立的总尝试数和时间上限 |
| P0-09 | 用量、收入与成本台账 | 关联逻辑任务、attempt、最终响应、用户扣费和上游成本；未知成本显示待对账，不伪装成零 |
| P0-10 | 运营后台 | 客户/Key 冻结解冻、订单/退款/拒付、价格上下架、渠道状态、待对账、告警和审计；最小权限、管理员强认证与入口保护 |
| P0-11 | 公开文档和客户端接入 | curl/Python/OpenCode 可复制样例；写明支持矩阵、余额不足、429、幂等冲突、流式中断和支持入口；不声称完整兼容所有 OpenAI API |
| P0-12 | 部署和运营交付 | 环境模板、部署预检、迁移、启动、监控、备份恢复、升级/回滚和首次商用验收清单；空密钥/测试渠道不能显示可收款 |

退款首发先完成“一笔购买订单的一次全额退款”及拒付处理，退款是否可执行须满足余额/占用检查和确认规则；部分退款、自动优惠和多币种延期。若真实渠道不能满足这个流程，先调整方案而不是伪造成功。

### 7.3 接口边界

以下是目标契约；存在同名旧接口时先审计兼容，不重复建接口，也不宣称已完成。

| 接口组 | 接口及职责 |
|---|---|
| 身份 | `/auth/register`、`/auth/verify-email`、`/auth/login`、密码恢复与退出；只处理身份，不发放未经确认的可消费余额 |
| 客户 Key | `/v1/keys` 创建/列表/吊销；创建需网页登录态；模型调用使用独立 API Key |
| 购买 | `/billing/checkout` 创建本站订单和托管支付会话；客户端带幂等键；金额从服务端有效 SKU 读取 |
| 回调 | 独立支付 webhook，校验原始报文签名后按事件和订单幂等入账；没有客户端“充值成功”接口 |
| 查询 | 钱包、订单、账本、用量与导出接口；按当前登录客户过滤并分页；导出防公式注入 |
| 模型 | `GET /v1/models`、`POST /v1/chat/completions`；API Key、预算、幂等和输出限制 |
| 任务 | 按请求 ID 或原幂等键查询处理状态，仅返回所属客户元数据；不保存或重放正文 |
| 运营 | `/ops/*` 下分离客户、支付、供应商、模型价格、对账、告警和审计权限；全部受强认证和审计保护 |
| 运行 | `/healthz`、受控 readiness、内部指标和维护任务；公网不暴露敏感配置或管理指标 |

关键关联：`Tenant → APIKey / Wallet / Order`；`LogicalRequest → ProviderAttempt → CostRecord`；`WalletTransaction → append-only LedgerEntries`；`OperatorAction → Object / Actor / Reason / OperationID`。供应商渠道与客户租户分属不同凭据域。

状态机最低要求：

- 订单：created → pending → paid / expired / failed；paid → refund_pending → refunded；拒付独立记录并防止重复冲正。
- 调用：accepted/reserved → running → settled / released / pending_reconciliation；状态不确定不得自动释放并重发。
- 同幂等键不自动新建任务；不保存回答导致无法重放原答案时，返回原任务 ID 和查询方式。必须向客户端明确这一限制。

### 7.4 技术路线与安全边界

- 沿用 GitHub、现有 FastAPI/SQLAlchemy/Alembic 内核、Supabase PostgreSQL/Vault 与 OpenCode 适配资产，不为改目标重写整套系统。
- Vercel 作为既定首选部署路径；分别验证控制台、API 流式时长、连接池、外部维护任务、请求体和并发约束。发现不满足时先提交具体失败证据和最小托管调整方案，不擅自换平台或采购。
- 新增明确的商业运行模式（名称暂定 `managed_gateway`），默认关闭。不能通过删除所有生产检查或启用 `legacy_test` 绕过发布门槛；保留 BYOK 的隔离测试与兼容性。
- 公共注册、真实支付、托管上游外呼分别有开关和预检；真实商户/供应商未配置时可运行模拟验收，不接受真实款项。
- 不保存提示词、回答、请求正文或正文哈希；请求 ID、供应商、模型、Token、价表版本、成本、失败类别、耗时和审计元数据足以追踪。平台日志不代表供应商零保留，客户条款需说明边界。
- 上游固定 HTTPS allowlist，不允许客户填写任意转发 URL；禁止携带任意管理请求头。限流、熔断和支付/调用并发状态使用跨实例共享存储。
- Key/支付密钥/数据库凭据进入受控密钥系统；平台上游 Key 不下发客户端，不写仓库；迁移和运行数据库角色隔离。
- 站点注册开放不等于匿名滥用：必须有邮箱验证、验证码/速率控制、模型权限限制、账户冻结、投诉处理、使用规则和允许市场的运营配置。

### 7.5 尚待确认的假设

1. 哪个主体和服务市场实际可使用选定支付渠道、供应商和部署服务。
2. 首个供给渠道及具体商业使用依据；首发先上 2–3 个通过计费验证的文本模型。单渠道可小范围试营运，但未接通第二个合格渠道前不宣称真实跨供应商容灾。
3. 一个支付渠道、服务售价、手续费、退款与拒付成本能否形成可接受的单位经济性。
4. Vercel 首选方案能否通过实际工作负载验收；不以本地健康检查替代。
5. 用户是否愿意持续购买，以及自有工具导流是否能产生付费。均未验证。

## 8. 分阶段发布与交付清单

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| A：差距与契约 | 基于本 PRD 审计旧注册/支付/钱包代码，设计商业模式与平台凭据域，固定计费和接口矩阵 | 每项标注复用/修改/新增，账本状态机与安全边界明确；不得靠打开测试模式上线 |
| B：核心闭环 | 注册/验证 → 模拟支付入账 → 托管模型模拟调用 → 扣费 → 退款/异常对账 | 正常与失败路径、并发、幂等、越权测试通过 |
| C：可运营站点 | 客户页、后台、模型价格、公开文档、账单导出、告警与 OpenCode | 新用户按文档独立完成模拟全流程；运营能排障和冻结风险账户 |
| D：受控预发布 | 干净构建、专用测试项目、迁移/恢复、入口保护、日志检查、流式和并发验收 | 自动检查与人工技术验收全部通过；无真实客户数据混入 |
| E：真实小额与首发 | 明确授权下接商户/供应商，真实购买、真实调用、账单核对、退款、域名与生产验收 | 所有收款/调用/退款有权威证据；确认具体发布对象与回滚点后才上线 |

时序按退出条件推进；阶段 A 后根据真实差距给实现工期，供应商/商户审批等待单列，不能伪装成可由代码保证的日期。下一步实施从 A 开始，紧接 B，不再重复泛泛市场分析。

首发交付物：GitHub 源码与 PR、锁定依赖和镜像、环境变量模板、数据库迁移、安装/配置/升级/回滚手册、客户接入文档、运营手册、测试与实网验收报告、已知限制和待办清单。

首发不做：订阅账号共享/逆向取 Key、匿名免验证滥用通道、无限额度、提现转账、渠道代理分销、复杂会员、多币种钱包、自动订阅续费、未经支持的图片/音视频计费、宣称任意 API 完全兼容、公众号完整业务系统。

立即停止开放收款/新调用的条件：密钥泄露或越权、重复入账或重复扣费、并发穿透预算、不可解释的账本差异、未知上游成本被自动清零、供应商/支付资格未落实、备份恢复失败。修复并重新验收后再恢复。

完成口径：本地完成、测试通过、预发布通过、真实支付/调用通过、正式上线、客户付费与复购分别记录。绝不再把 BYOK 候选版交付解释为公共商业中转站完成。
