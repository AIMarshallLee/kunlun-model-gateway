# 购买入口与已配置供给一致性

范围：商业 PRD P0-03/P0-06/P0-12。修复收款配置存在但没有已配置的上架模型供给时，页面仍提示可购买、服务端仍创建支付会话的问题。不是正式支付 SDK 或供应商健康验收。

## 统一判断

`has_configured_supply` 只读取允许目录、平台 Vault 渠道元数据和当前上架价表。至少一个当前上架、存在于运行配置中的模型，经允许目录中的已启用且非 `pending_cleanup` 渠道提供，才判为有已配置供给。

- 没有渠道、全部禁用、清理待处理、仅未知渠道、全部模型下架或 Vault 元数据读取失败：不允许新购买。
- 允许目录外渠道、未上架模型不能使状态通过。
- 同步数据库读取失败时保守拒绝；不使用旧缓存当作成功。
- 不读取／解密平台 Key，不向模型供应商发探测请求，也不产生探测 Token 费用。

这一判断是配置快照，不是供应商服务可用性承诺。已有 active 元数据不能证明凭据没有被供应商吊销、余额足够、模型健康或用途已授权；绕过受控写入直接破坏 Vault 的情况仍需独立检查与告警。确认真实供给和正式支付仍是发布门槛，不能因为此布尔值为 true 就开放商用。

## 接口与页面行为

| 入口 | 行为 |
|---|---|
| `GET /public/catalog` | `purchasing_enabled` 在原生产／正式支付配置条件之外，还要求支付渠道名称及已配置供给；不公开渠道名称、Key、内部成本或故障细节 |
| `GET /billing/packages` | 保留 `packages`，新增 `purchasing_enabled`；客户控制台据此隐藏新购买表单和“开始另一笔购买”按钮，显示双语暂停说明 |
| `POST /billing/checkout` | managed 模式在创建订单、申请 checkout claim 和支付方外呼之前重新检查供给；不可用返回 503，不新增订单或支付会话 |
| 订单／原幂等键查询、付款回调、退款和对账 | 不加供给门禁；已接受的支付事实仍须处理，不能因停供丢账或静默退款 |

新购买表单在读取套餐／供给状态成功前保持隐藏，读取失败不会默认开放。旧页面可能在暂停前已加载购买按钮，服务端仍会拒绝新的 checkout POST。页面不自动轮询、不自动生成新幂等键；客户可以刷新查看当前状态。暂停后同一 checkout POST 也可能被拒绝，此时按原请求编号调用 `/billing/checkout/lookup` 或查询订单，不以 503 推断原订单不存在。

检查之后、支付方调用之前或第三方收银台打开后，供给仍可能改变；这不是跨 Vault／模型／支付方的原子事务。本批不撤销已生成的第三方收银链接、不阻断已付款回调、不做自动退款。期间发生支付时正常入账，再按明确售后规则处理。已有订单继续显示其真实状态与原恢复入口。

测试环境中的 `purchasing_enabled` 只允许显式注入的模拟支付流程；公共首页仍不把测试环境标记成可真实收款。原 `legacy_test` 和 BYOK 的独立边界保留，生产仍禁止测试支付。

## 验证

- 先复现公共 `purchasing_enabled=true` 与无供给的错误，再实现统一检查。
- Python 覆盖六类无供给状态、阻断零订单／零支付调用、恢复后同键只创建一次、停供期间订单查询与已付款回调正常；额外确认既有空白 Key 拒绝规则，没有修改凭据写入算法。
- 浏览器 `tests-browser/purchase-supply.cjs` 使用 `checkout_fixture.py --no-supply` 的全新 loopback 隔离夹具：暂停页面、过期页面触发服务端拒绝、供给恢复后沿用原键、仅一次模拟 checkout、停供后付款事件和订单查询、中英文／手机布局。
- 原 `tests-browser/checkout.cjs` 在无参数的新夹具上回归丢失响应、同键恢复、单次支付方命令、回调入账和退出清理。夹具新增的供给切换路由仅操作内存假 Vault，不进入应用包。
- 图像证据在忽略目录 `release-artifacts/purchase-paused-mobile-zh.png` 与 `purchase-paused-desktop-en.png`；仅合成账户／金额，不能当客户或收入案例。

本地验收：531 项 Python 测试、49 项 TypeScript 测试及类型检查通过，分支覆盖率 84%；购买供给专项、原支付恢复、完整中英文身份／控制台浏览器流程通过。沿用既有界面样式，已目视检查手机与桌面暂停状态；保留一项既有 Starlette/httpx 弃用警告。云端 CI 以对应提交的结果为准。

无 schema 迁移、依赖升级、真实密钥修改、模型调用或收费。回退本批代码会移除新的购买门禁，不代表供给已恢复；事故处理应先暂停新收款，保留原订单、幂等键、钱包和全部审计。不要删账回滚。

完整商业上线仍待正式 SDK／商户、真实供应商与计费核验、强认证与入口、受保护预发布、真实小额支付／调用／退款、恢复与容量验收。
